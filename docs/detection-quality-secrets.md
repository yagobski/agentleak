# Credential coverage

The [detection-quality page](detection-quality.md) measures personal data.
Credentials need a different question: not "is this value sensitive" but "does
the deterministic tier know this provider's format at all". A leaked key is
the most actionable thing an agent can disclose, and the most common thing a
coding agent handles.

## What is measured

`scripts/secret_samples.py` generates three synthetic tokens for each of 53
formats — provider keys and tokens (cloud, code hosting, package registries,
messaging, payments, AI providers, observability), JWTs, private keys and
connection strings. Tokens are built at run time from a seeded generator, with
every prefix split by concatenation, so no token-shaped string is committed and
none was ever a live credential.

Each token goes into three carriers — a sentence, a bare log line and a JSON
value under a neutral key — and counts as found when any of them yields the
expected data type with a matched value that contains the token or sits inside
it. A token found only as some other type counts as a miss.

Precision is measured on the language-neutral hard negatives of the English
page: the share of those texts on which any *credential* type fires, through the
full fast pipeline (placeholder keys such as `sk-xxxx…`, `${VAULT_SECRET}`,
`<your-api-key>`, credential-less DSNs to `localhost`, hashes, UUIDs).

## How to read the result

**159 of 159 tokens found, 53 of 53 formats** (36 of 159 and 12 of 53 on
0.18.0, which knew AWS, GitHub, Slack bot/user, Stripe, OpenAI/Anthropic,
Google API keys, JWTs, private keys and URL connection strings). **0 of 82**
hard negatives flagged with a credential type (8 of 82 on 0.18.0: placeholder
keys and `localhost` DSNs).

This is a coverage measurement on formats chosen and generated by the same
author as the rules. It shows which formats are recognised; it does not show
how the rules behave on real-world keys, which a public repository cannot hold.
Formats with no distinctive prefix (an AWS secret access key, a Twilio auth
token, a Cloudflare global key) are found only through the key name that holds
them (`aws_secret_access_key = …`), by the generic assignment rule, and are not
in this table.

## Reproducing

```bash
python scripts/detection_quality_secrets.py                       # table
python scripts/detection_quality_secrets.py --json report.json    # every number
python scripts/detection_quality_secrets.py --installed           # another installed version
```

`docs/detection-quality-secrets.json` is the full machine-readable report.
